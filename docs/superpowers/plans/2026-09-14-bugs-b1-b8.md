**Contexte / cause racine :** `findStepIdsAndDonesBySubmission()` retourne **tous** les tokens (sans filtre `invalidated_at`). Un token invalidé par RGPD a `done_at IS NULL` + `invalidated_at NOT NULL` : `WorkflowAdvancer` le compte comme « étape démarrée » (`$allStarted` vrai) mais `isGroupComplete()` est faux (done_at null) ⇒ il sort en attente **à vie**. En excluant ces tokens, l'étape n'est plus « démarrée » et `createTokensForGroup()` recrée un token actif + renvoie l'email.

## Notes de conception (justifications)

- **Pourquoi ne pas filtrer `invalidated_at` dans `findForExport` (B6)** : l'export doit rendre l'état discernable — un token invalidé doit apparaître avec `invalidated_at` renseigné, pas disparaître.
- **Pourquoi `MailInterface`** : `MailService` est `final readonly`, donc non doublable. L'interface `App\Contract\MailInterface` existe déjà et est mise en œuvre par `MailService` ; les sites de construction (bootstrap, `phpunit_bootstrap`, tests) passent déjà une instance `MailService` — changement purement local au typage.
- **Pourquoi `finally` dans `advance()`** : la méthode a plusieurs `return` après commit ; le `finally` garantit que les notifications collectées sont envoyées hors transaction sur tous les chemins commités, sans dupliquer le flush à chaque point de sortie.
- **`formatDelay()` non modifié** : `done_at` et `sent_at` sont tous deux UTC ; leur différence est invariante au fuseau. Le corriger serait du bruit sans effet.
- **`remind.php` testé en caractérisation** : le refactor est sans changement de comportement observable ; la garde d'écriture (UPDATE conditionnel + `rowCount`) est conservée et vérifiée par le test de caractérisation. La preuve « SMTP hors transaction » est portée par le test `WorkflowAdvancerMailTransactionTest` (seam direct), impossible à reproduire pour un script CLI de façon déterministe.
